# SMD, SMAP, and MSL benchmark data

Prepare all real benchmarks with:

```bash
.venv/bin/python -m scripts.prepare_benchmarks --dataset all
```

`setup_ubuntu.sh` performs this step automatically, validates the three
datasets for seeds 42, 43, and 44, and writes
`datasets/partition_manifest.json`. Archives and extracted data are ignored by
Git.

## Mapping natural entities to 100 sensors

The paper uses the same physical topology for every real benchmark:

```text
N = 100 stationary sensors
M = 10 mobile fog/AUV aggregators
```

Natural dataset entities are not treated as the 100 physical sensors. Each
machine/channel timeline is first split into contiguous, non-overlapping
shards:

| Dataset | Loaded source entities | Allocation to 100 clients |
| --- | ---: | --- |
| SMD | first 10 machines (`D=38`) | 10 shards per machine |
| SMAP | 54 unique channels in the bundled metadata (`D=25`) | 46 longest channels x 2, 8 x 1 |
| MSL | 27 channels (`D=55`) | 19 longest channels x 4, 8 x 3 |

The implementation derives the allocation from the actual entity count:
every entity receives `100 // E` shards and the longest `100 % E` entities
receive one additional shard. This also handles a source package with a
different channel count without hard-coding 54, 55, or 27. Duplicate metadata
rows for one physical channel are merged (the bundled SMAP metadata lists P-2
twice), so its timeline is never loaded twice.

For each entity, the first 80% of its official normal training sequence is
used for local training and the remaining 20% for normal-only threshold
validation. The training portion is split only after this temporal
train/validation boundary is established. Timestamps are never shuffled
before sharding, and no training row is duplicated or dropped.

After sharding, the 100 data-client identities are permuted onto the 100
sensor positions using the experiment seed. This prevents machine/channel
identity from being accidentally correlated with sensor numbering or fog
assignment. The same seed therefore produces the same data-to-topology
mapping for every compared method.

Official test sequences and inclusive anomaly ranges remain unchanged and are
used only for evaluation. The main reported score is pooled global F1/PA-F1.

## Synthetic heterogeneity controls

The paper's strong non-IID (`alpha=0.1`) and near-IID (`alpha=10^4`) control
in Fig. 7 is generated by the synthetic scenario. It is separate from the
natural, entity-preserving real-data partition above.
